# Tawjihi Knowledge Base — Data Report

Generated by the Data Architect pass. All output files are UTF-8 with Arabic preserved
(`ensure_ascii=False`). Source of truth: `cleaned_data_fixed.csv` (admissions) and
`university.html` (rich speciality content).

## Files produced (under `tawjihi/data/kb/`)

## Row / record counts

- **CSV physical lines:** 8,499 (this is the number quoted in the PRD).
- **Actual CSV data records:** **4,445** (+1 header). The gap is caused by quoted fields
  containing embedded newlines (multiline `Etablissement` / `Filiere` values). Parsed with the
  stdlib `csv` module, which correctly reassembles them; internal newlines collapsed to single spaces.
- `admissions-full.json` → **4,445 rows** (asserted equal to CSV data records).
- Establishment type split: `university` 4,418 · `grande_ecole` 24 · `national` 3.
- Rows with all three stream thresholds null (`NC`/`--`, i.e. opens no stream in 2025): **1,587**.
- `filiere-index.json` → **3,137 distinct filiere labels**.

## Stream mapping

`min1 → sciexp (علوم تجريبية)`, `min2 → math (رياضيات)`, `min3 → techmath (تقني رياضي)`.
`NC` and `--` are stored as `null`.

## Wilaya extraction coverage

- **4,435 / 4,445 = 99.8%** of rows carry a best-effort wilaya (FR spelling).
- Method: 60-wilaya gazetteer + special-case map (concatenated spellings like `ELOUED`→`EL OUED`,
  `KOLEA`→`TIPAZA`, `USTHB`/`BAB EZZOUAR`/`BEN AKNOUN`→`ALGER`) + `UNIV.`/`UNIVERSITE D/DE` /
  `CENTRE UNIV.` / school `… DE/D <X>` patterns. ENS annexes resolve to their host wilaya.
- The **10 remaining nulls are by design**: 3 `RECRUTEMENT NATIONAL` rows (no wilaya) and 6 national
  grandes écoles (Nanosciences, Systèmes Autonomes, IA, Mathématiques, Télécoms/TIC, Conservation des
  biens culturels) recruited nationally with no wilaya token in the name.

## Speciality linking coverage (113 total)

- **63 / 113 specialities linked to ≥1 filiere** in the first pass (see SECOND PASS below: now
  86 / 113 carry non-null `resolvedAverages`).
- Linking method: deaccented French/English token overlap between each speciality's keywords
  (`data-name` + `name_fr` + section heading titles + a small curated alias map for stemming gaps
  such as `MATH→MATHEMATIQUES`, `BIOLOGIE→BIOLOGIQUES`, `LANGUES→LANGUE`, `vetrinaire→VETERINAIRES`)
  and each filiere label. A match is accepted when the filiere is ≥60% token-covered, OR ≥2 tokens
  overlap, OR a single shared token is *distinctive* (appears in ≤40 filieres). Matches are ranked
  most-specific-first and capped at 30 per speciality.
- Categories present in the HTML (8, not the 5 in the PRD): engineering 32, medical 24, double 22,
  science 14, business 12, humanities 6, law 2, education 1.
- **101 / 113 specialities carry `averages_text`** (extracted 2025/2024 admission-average lines).
- All 113 detail blocks were located (0 missing).

## Speciality linking — SECOND PASS (grande-école recovery)

The first pass linked on *French filière-label tokens*, which fails for grandes écoles because they
recruit **by school**: in the CSV their info lives in the `etab` field and in `FB … ECOLE …`-prefixed
`filiere` strings (e.g. `etab="ECOLE NATIONALE SUPERIEURE EN INTELLIGENCE ARTIFICIELLE"`,
`filiere="FB INF ECOLE NATIONALE SUPERIEURE EN INTELLIGENCE ARTIFICIELLE ALGER"`). The card carries an
Arabic name + a latin school acronym in `dataName` (e.g. `"ENSIA ذكاء اصطناعي الجزائر"`).

Second pass re-matches on **establishment name** by scanning deaccented/upper `etab + filiere` for a
distinctive full-name substring per school, then records on every speciality:

- `linkedFiliereKeys` — filière keys of the matched rows (the `FB …` school strings).
- `linkedEtabRows` — **new** field: exact row indices into `admissions-full.json.rows` for the matched
  establishment rows, so school-recruited specialities carry their averages even without a clean filière.
- `resolvedAverages` — `{min1,min2,min3}` = best (lowest non-null) threshold across all matched rows.
  Computed for **all 113** (first-pass filière-linked ones get best across their `linkedFiliereKeys`).
- `_linkNote` — updated to the new state.

**Coverage: 86 / 113 specialities now carry non-null `resolvedAverages` (was 63).**
26 grandes écoles recovered; all resolved averages fall in a plausible 13.8–19.0 band. Cross-check:
ESTIN's own card text ("رياضيات 17,45 / علوم تجريبية 17,79 / تقني رياضي 18,15") exactly matches its
resolved `{17.45, 17.79, 18.15}`, confirming the row match and the `min1=sciexp/min2=math/min3=techmath`
stream mapping.

## Data anomalies observed

- `Min` values use both `.` and `,` as decimal separators in the source (e.g. `17,15`); both normalized to float.
- `--` appears alongside `NC` as a "does not accept" marker; both → null.
- Several `Filiere` and `Etablissement` cells span multiple physical lines inside quotes (handled).
- Some school names have typos in the source (`NANOTECHENOLOGIES`, `TECHNOLOGIE DE TIC`); left as-is in `etab`.
- The HTML uses 8 `data-category` values, more than the 5 named in the PRD.
- Speciality detail blocks are structurally heterogeneous (mix of `<h2>`/`<h3>` headings, `intro`,
  `detail-card`, `modern-section-header`); the extractor keys sections by `<h2>`/`<h3>` title text and
  falls back to `_full`/`_section_N` when a block has none.
